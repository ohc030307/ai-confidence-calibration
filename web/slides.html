그런데, 안경 속 AI가 "99% 확신, 정답은 3번"이라고 하면
그대로 적어도 될까?

출처: BBC 코리아(2026.11.19), 연합뉴스(2026.11.17)

문제

사람은 AI의 확신도를 보고 검산할지 정한다

"99% 확신해요" → 그냥 믿는다
"60% 정도요" → 한 번 더 확인한다

그러니 확신도가 실제 정답률과 맞지 않으면,
사람은 틀린 답을 가장 확신할 때 믿게 된다.

질문 1. AI의 확신도는 실제 정답률과 맞는가?
질문 2. 어떤 문제에서 자신 있게 틀리는가?
질문 3. 그걸 줄이는 방법이 있는가?

10월 예비 시험 (20문항, 1번씩)

Gemini: 16개 정답, 틀린 4개 포함 전부 확신도 100%

Claude: 20개 정답, 확신도 90~99%

→ 20문항으로는 결론을 낼 수 없어 본 실험으로 확장

방법

정답이 확실한 문제 141개를 모델 5개에게

① 문항 141개수학 61 · 컴퓨터 80
계산·코드 문항 정답은 코드로 직접 계산
유명 문제는 숫자를 바꿈
② 난이도 사다리곱셈·요일·코드 추적·글자 세기 등 6종을 10단계로 점점 어렵게
③ 모델 5개Claude Haiku · Sonnet · Opus 5.5
Gemini 3.5 Flash · Flash-Lite
매번 새 대화, 도구 끔
④ 답 + 확신도{"answer", "confidence": 0~100}
Claude는 문항마다 3번 반복
→ 규칙으로 자동 채점

지표: ECE(확신도와 정답률의 평균 차이, 0이 이상적) · AUROC(확신도로 맞은 답/틀린 답을 가려내는 정도, 0.5=못 가림) · 자신 있게 틀림(확신도 90% 이상인데 오답)

어려워질 때 확신도도 따라 내려갈까

실선 = 실제 정답률, 점선 = 말한 확신도 (Claude 3개 모델)

12자리 곱셈·코드 추적은 끝까지 거의 다 맞힘 → 틀린 곳은 '긴 문자열 세기'에 몰림. Claude는 이때 확신도를 낮췄지만 정답률만큼은 아니었다.

검증

결과를 믿을 수 있는지 어떻게 확인했나

정답이 맞나

계산·코드 문항 정답은 사람이 아니라 코드가 계산 (파이썬·노드로 실행)

채점이 맞나

"2,812,160원", "65%", "[1, 10, 3]"처럼 같은 답을 다르게 써도 맞게 채점하는지 테스트 50개 통과

문항이 공정한가

응답을 살펴보다 문항 오류 발견: "1026년(그레고리력) 요일" → 그레고리력은 1582년 도입이라 '전제 오류'도 맞는 답 → 정답 인정 후 재채점

같은 질문을 Claude에 3번씩 → 한 번의 우연이 아닌지 확인 · 원본 응답 전부 공개(results/raw)

개선

발견한 문제 → 고친 방법 → 다시 확인

발견: 쉬운 문제에서 한 번씩 실수하고도 확신도 98~99%
Opus "1~200 중 3 또는 7의 배수 개수" → 86 (정답 85), 확신도 98
Haiku 행렬 거듭제곱 → 144 (정답 10946), 확신도 99

고친 방법 ① 점검 프롬프트
전제 확인 → 다른 방법으로 검산 → 세기는 10개씩 묶어 세기 → 검산 결과로 확신도 정하기

고친 방법 ② 3번 물어보기
같은 질문을 새 대화로 3번 → 답이 다르면 "검산 필요"

개선 ②

3번 물어보면 '자신 있게 틀린 답'이 잡힌다

한계와 남은 과제

이 결과를 어디까지 믿어도 되나

  • Gemini는 무료 한도 때문에 기본 81문항을 1번씩만 물었다 → Claude보다 응답 수가 적다
  • 점검 프롬프트는 자신 있게 틀린 답을 없앴지만, 확신도를 전반적으로 더 낮춰 ECE는 조금 나빠졌다 (원래 약간 겸손했던 모델이 더 겸손해짐)
  • 3번 물어보기는 비용이 3배 → 중요한 답에만 쓰는 것이 현실적
  • 수학·컴퓨터 문제만 다뤘다. 정답이 애매한 분야(법, 의료, 시사)는 따로 확인해야 한다
  • GPT 등 다른 회사 모델은 포함하지 못했다 (유료 API)

AI의 확신도는 '정답의 증거'가 아니라
모델마다 따로 검증해야 하는 숫자다.
